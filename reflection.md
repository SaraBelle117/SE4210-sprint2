# Reflection

## Experience
Overall, I enjoyed creating this visualization for buffer overflow for Learning Sprint 2. If I had to do this assignment over, however, I may have started earlier so I could make it a bit more interactive and complex (a more fleshed out stack visual, and maybe even a teeny bit of animation). Additionally, I may have chosen a more sophisticated method than just plain HTML and JS, as I am much more comfortable using Bootstrap or React. As I did this Learning Sprint on my own, I had a bit less time to dedicate to this portion of the sprint, which is why the end result is more simplistic. In general, this did remind me of why I tend to gravitate more towards backend development (and am not a huge fan of HTML), but overall, I think challenging the things I am not as good at (or enjoy doing a bit less) is always a good exercise. 
## What This Helped Me Understand
Buffer overflow is something I learned very early on in my CS education, but this course was the first to formalize it with the actual mechanics, terms like EIP and EBP included. Nonetheless, when I was in the early development phase for this part of the assignment, I initially wanted something a lot more complicated (i.e., animation). This part of the design did not come to fruition due to limitations with time, and admittedly, a limitation with my own ability. 
## Workflow
I made every single design decision for this interactive web visualization, using the graphics provided in class, as well as some inspiration from some of the Zybook activities I used in the earlier courses for my degree. To simplify the development process (and avoid pouring through documentation for CSS and HTML), I used Claude (Sonnet 5) to speed up this process, as well as ensure the underlying mechanics (buffer overflow detection, the EBP/EIP overwrite simulation) were technically accurate. I directed every design and functional decision, iterated through several rounds of feedback on the UI, and had Claude generate and refine the HTML, CSS, and JavaScript to match. Given that I completed this project alone, whereas most of my classmates worked in groups, time constraints were the main driver behind using Claude here; the project itself wasn’t technically demanding, just time-consuming to hand-write from scratch (especially considering my programming expertise is not frontend development).
